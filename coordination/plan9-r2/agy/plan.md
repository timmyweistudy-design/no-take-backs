## 3. 角色與動畫（需求 1）
### 3.1 步態：Q 版跳步，由位移驅動
**結論**〔C 合併 X、G〕：不做寫實踏步，豆豆腿畫不出膝蓋，動作也不可愛。改成微跳步與搖擺步，但節奏仍由真實位移決定，這樣不會滑。

- **相位**：每隻累積世界位移（不是螢幕座標，否則受擊偏移會污染），`phase = 累積距離 / 步長 × TAU`，用既有內插值 `accum` 內插〔X〕。減速圈、碎石、變速播放自動正確。
- **重播跳轉**：跳轉重跑時同步累積，或存畫面檢查點；單位出生時初始化〔X〕。
- **拖行不算走**：被擊退、被吸走切專屬姿勢，不累積走路相位；被擠開才算小碎步〔X〕。
- 純畫面，不進模擬，指紋不變。
- **腳底基準線**：起伏只動上半身；只有跳步騰空段才整隻離地，影子同步縮放。
- **影格**：走路 6→8 格（程式繪製，不增加手工），另加拖行、暈眩 2 格，每種 26→28 格；每頁 7 種會超過 4096，改 6 種，並消除烘焙硬編碼〔X〕。實作時量記憶體。
- **分層貼圖**：先不做。只有部件共用且裁切後才省，貼圖命令至少加倍〔X〕。

## 4. 地圖（需求 3）
### 4.1 原則
- 全部左右鏡像，鏡像測試繼續成立。
- 地形只留一眼懂的：擋路、慢、快。**砍草叢、高地**〔X、G〕：草叢要改選敵並影響投彈兵切換，而且玩家看不到 2 格圈；高地在俯視角看不出高低，0.5 格也無感。
- 平原＋中型走舊路徑，位元組不變；不追加雜湊。舊代碼不受影響。
- 地圖只用於自由排兵。

### 4.2 大小
| 大小 | 格數 | 建議金／人數／秒 |
|---|---|---|
| 小 | 12×7 | 60／16／60 |
| 中（標準） | 16×9 | 100／24／90 |
| 大 | 18×10（原 20×11 太糊）〔G〕 | 130／30／120 |

大地圖鎖定血條與文字最小像素。大小要貫穿部署邊界、複製、全場縱深、鏡像、UI 硬碼、代碼解碼〔X〕。

### 4.3 地形
| 地形 | 規則 | 例外 |
|---|---|---|
| 擋路（岩、樹、河、熔岩） | 地面單位不能過 | 幽靈、沙漏精靈可過；箭、火罐飛過去；孢子圈穿透 |
| 慢（泥、雪、沙） | 移速 ×70%，和孢子、碎石的減速取最低不相乘 | 幽靈、沙漏精靈不受影響 |
| 快（石道、冰） | 移速 ×120% | 同上 |
| 噴口（最後才加，可砍） | 每 8 秒預警 1 秒後噴發，範圍傷害不分敵我 | |

### 4.5 模擬實作〔X〕
- `W`/`H` 改場次欄位，舊常數入口保留；量效能回歸。
- 地形是整數矩形與圓清單，進規則摘要、規則代碼 NTBR4、外層對戰碼與陣型解碼。
- **尋路**：0.5 格小格網，依目的格快取整數 BFS（有快慢才用 Dijkstra）；固定「隊伍視角」破同分確保鏡像；障礙要膨脹、禁切角；找可達的攻擊點。有地形才走這條，平原不碰。
- **技能**：騎兵路標、刺客背後點、吸引、推擠、擊退都要掃掠碰牆，擊退維持先合計再裁切；分裂、復活落點要合法且鏡像。
- `to_free` 放不下目前會少兵，要改成必定成功或明確失敗。
- 卡住偵測；全場「無處可放」搜尋隨面積變大要量。
- 工具：地圖 JSON、驗證（鏡像、可達、部署面積）、`golden_map`。每張圖以一份設計縮放成 3 種大小，驗證不過可覆寫。
- AI：陣型模板依地圖調權；困難 AI 本來就用模擬挑陣；反制庫只用標準。
- 平衡：每圖每大小跑 army、cheese、repl；只有平原中型有認證，其他「娛樂」徽章。

### 4.6 美術與音效
每圖一張烘好的背景；前景物件與角色依 y 排序可遮擋；地形邊緣有過渡與高度陰影，一眼看出能不能走；地圖卡有縮圖；每圖一段環境音與腳步材質；黃昏、夜晚只是外觀。素材程式繪製優先，缺口用 CC0（Kenney），記到授權檔。Cainos 現有條款要再確認能否改色。

| 重播 | 時間軸太細 → 加粗、標首殺與團滅 |
| 覆盤 | 難比對 → 「勝率 +12%」大徽章 |
| 遠征選軍 | 黑底小圓鈕 → 兩張軍團旗幟卡 |
| 暫停、確認框、代碼輸入、按鍵、製作名單 | 統一元件、補焦點與音效 |

### 7.4 音效
- 介面：懸停、確認、返回、頁籤、滑桿、錯誤、彈窗、解鎖。
- 戰鬥：腳步（小音量＋數量上限＋地形材質）、武器材質打擊、技能分層、結果號角。
- 音樂：畫面交叉淡入、技能時壓低音樂、匯流排分開。
- 來源：合成音保留當層次，主體換 CC0（Kenney、Freesound CC0），全部記授權。

### 7.5 看懂度驗收
版面檢查新增左緣對齊、留白比例、對比度、圖示文字配對、主要按鈕唯一；每畫面問 Antigravity「3 秒內看得懂要做什麼嗎」；裝飾不能搶數值（〔參考〕juice 過量反而傷害可讀性）。設定保留減少動態、關震動。

## 8. 程式與資料夾（需求 6）
- 拆檔順序〔X〕：純繪製 → HUD → 畫面流程；保留入口與載入路徑。`Art` 有共享靜態狀態，不能只照兵種剪貼；工具搬移另一批。
- 目標結構：`ui/screens/`、`ui/hud/`、`ui/units/`、`ui/widgets/`；`tools/check|balance|gen|dev/`。
- `coordination/` 打包舊輪、`.log` 不進 git；`docs/` 舊方案與舊截圖進 archive，`docs/shots-v7` 移除。
- `projects/ntb-*` 看過內容後移到 `build/old-shots/`（不進 git）或刪；專案暫存放 `build/tmp/`，`tools/clean.sh` 一鍵清。
- `play.bat` 不寫死路徑。

## 9. 省 token、skills、效能、驗收加速（需求 7）
### 9.1 驗收加速〔X〕
- 先幫每項計時，再決定改什麼；45→8 分鐘是目標不是硬門檻。
- 測試依 suite 分片，每片獨立 user 目錄（目前 Save／Steam 靜態狀態與固定檔名共用，`run_tests.gd:21`、`tests/suites/save.gd:18,99`）。
- 金標準、相容、鏡像支援分片並行。
- 依變更挑檢查：快取鍵含引擎版本、工具、相依資料；只改 UI 仍跑載入、啟動、字型。
- 版面檢查分快速與完整；所有工具單行結論；逾時用 PID 收 Windows 程序。

### 9.2 省 token〔C〕
- 專案 `CLAUDE.md` 60 行內：入口、指令、鐵則。
- 專案 skills：`ntb-check`、`ntb-review`（三方流程與字數上限）、`ntb-balance`、`ntb-shots`、`ntb-unit`。
- MEMORY.md 瘦身：每個專案 1 行。
- 看圖先拼接觸表；審查提示模板化；長日誌不進對話；工具結果單行。

### 9.3 遊戲效能
門檻用同次舊基準比值（機器會差 3 倍）；貼圖格數算記憶體；圖示與背景烘焙；目標 48 隻 60fps（中階）、30fps（最低）、啟動 3 秒內。
