# V1.0.0 實作裁決紀錄

方案：`docs/2026-11-10-v1.0.0-plan.md`（討論 `coordination/v100d/`）。測試組 `v100`（`tests/suites/v100.gd`）。

## 實作中的決定
- **P0 W1／W2**：排行榜改成全部請求一條通道（不是每個榜一條）：同時一筆在途；找榜回呼用榜名對、上傳／下載用 handle 對；找榜失敗、逾時（15 秒）都只結束在途那一筆，下載回空清單；逾時後暫停 3 秒讓遲到回呼過去（遲到的對不上 handle／榜名就丟）；上傳限額任意 10 分鐘 10 次（Valve），超過留在佇列、下載可以先走；佇列裡同一個榜只留最新一筆上傳。每日高手陣畫面另有 `dt_gen`：離開或重開過，舊下載結果不寫畫面。
- **P0 W3**：`storeStats()` 回 true 只算送出；接 `user_stats_stored`，結果不是 1（OK）就 `store_ok=false`，約 600 幀後把本機成就整批 `setAchievement` 再送。`setAchievement` 回 false 也記重送。啟動補送照舊。
- **P0 M13**：三考背景運算的 `ctl` 建立時就放好 `stop`／`until`（主執行緒只改既有鍵的值，背景只讀）；`PZ.play` 帶 ctl 時逐 tick 跑、每 64 tick 看期限與取消。被取消的執行緒放 `trio_old`，`_trio_jobs` 每幀回收已停的，不在主執行緒等；`_exit_tree` 先叫停再等（64 tick 內停）。逾時（20 秒）回空 → `trio_err`，結算頁寫「算太久，這次不記星數」。`Thread.start` 失敗就在主執行緒照算。輸入深複製。
- **P0 M15**：作者解重跑期限 8 秒（三考 3 倍），超過回 `ws_slow`；仍在主執行緒（解碼是同步 API），最壞卡 8 秒，不再無上限。
- **P0 D3／D4**：壞檔隔離找不到空編號就用時間戳記名；改名失敗改「複製再刪」，都失敗記 `quarantine_failed`（主檔留原地，`save_data` 只輪替驗證過的主檔，所以不會蓋備份）。回報：寫檔與剪貼簿各自確認（剪貼簿寫完讀回比對；headless 一律算失敗），四種提示。
- **P0 T2／R0**：自我檢查加 `title`／`focus`／`size`／`version`；`export_check.sh` 要求 `"ok":true`、可選 `EXPECT_VERSION`、Linux 試玩版也啟動、輸出 `manifest.txt`。
- **版本號**：`project.godot` 1.0.0、`export_presets.cfg` file／product version 1.0.0.0（四處）。
- **H1／H2 入口**：照方案五牌。內部 id 沿用（`hub_challenge` 現在是殘局牌、`playroom` 改走通用卡片面板），少改返回與測試；`HUBS` 常數給建議下一步、測試共用。遊戲間舊的專用畫面 `_draw_playroom` 刪掉（眼力分、車輪最佳改到卡片面板底下 `hub_note`）。每日「今天還沒打」小牌移到遊戲間木牌。**不照方案**：新玩法導覽沒有移到系統列（150% 字級第四顆鈕放不下），留在收藏卡片＋建議下一步。單人遠征卡片鍵 `menu_gauntlet` 不標「新」（`NEVER_NEW`）。
- **M1**：「剋制互動一關」改成教學第 2 關開場提示 ▲▼ 怎麼看（不新增教學關：教學進度是數字，加關會讓老玩家的教學變成沒完成）。
