**1．逐面向建議**

各項依「問題 → 做法 → 優先度／里程碑 → 驗收」排列。P0＝下一批先處理；P1＝首發必需；P2＝視試玩取捨；P3＝發售後。

A．**核心規則**：目前驗的是戰鬥，未驗落子博弈 → 暫留16×9、每邊6欄、100金、24隻、90秒、60秒狂熱、三戰兩勝與最多5局；輪流落子主打、盲擺標明約定制。分開測先手與左右優勢 → **P0／M1–M2** → 同等策略至少200組交換先手；超過55%列調查，不直接判失衡。

B．**平衡**：10/10僅代表固定方陣成立；刺客陣23%不能直接推出刺客應降價 → 建200陣訓練池＋50陣保留池，爬山搜尋兵種、位置與落子順序；勝／平／負分列，報樣本與搜尋預算 → **P0／M2** → 保留池維持現有激烈指標；找到高勝率陣須附至少兩種可行反制。搜尋沒找到不等於證明不存在。

C．**AI**：六套模板不足以代表難度 → 簡單容許配置失誤；普通擴至12套；困難用離線反制庫。公開落子可讀當下公開資訊，盲擺只能讀歷史；全部守相同預算 → **P1／M5** → 困難對普通交換位置勝率≥65%；決策p95≤200ms，無現場大量模擬。

D．**內容**：30關、遠征與障礙同時承諾過大 → 先3教學＋10挑戰驗證，再擴30關；7場遠征只換兵、不加永久能力；障礙與新模式延後 → **P1／M5–M7** → 每關至少兩類解法，外測者能說出不同戰術。

E．**擺放UX**：不可收回容易變誤觸懲罰 → 拖曳放開前預覽、手把格子游標、醒目回合提示；3格存陣，輪流模式只作參考、不自動整陣落子；分享碼含版本、長度限制與校驗 → **P1／M3** → 雙輸入各完成整場，無越權或非法陣型。

F．**激烈演出**：殘兵少不代表最後才知勝負 → 找10人各玩3場，記錄「何時確信勝負」、激烈度與再玩意願；拔河條明示剩餘戰力。戰報列破盾、衝鋒、背刺與耗損，精彩片段依事件選取 → **P0／M4提前** → ≥7人評激烈度4/5，≥7人願再玩；慢動作不遮關鍵交戰。

G．**美術**：缺劍、缺馬且來源未明 → 先建逐檔來源／授權／動作表，再補同風格武器與坐騎；腳底錨點、方向映射、Y排序統一 → **P0／M3** → 48隻混戰下，測試者2秒內辨認五兵種≥90%。

H．**聲音**：核心回饋缺席 → 先補落子、命中、破盾、衝鋒、死亡、狂熱；同類聲音限流，音樂／效果分軌 → **P1／M4** → 48隻交戰不爆音，盲聽能辨三種關鍵事件。

I．**UI／在地化**：硬寫文字難維護 → 字串鍵值化，首發繁中／英，預留30%文字膨脹；中文目標16px；採[Noto OFL字型](https://notofonts.github.io/noto-docs/website/use/)並保留授權 → **P1／M3** → 無缺字、截字，兵卡與規則同源。

J．**無障礙**：顏色與鏡頭效果可能妨礙理解 → 隊伍形狀標記、100–150%字級、震動／閃光／慢動作獨立開關、觀戰速度 → **P1／M3–M4** → 灰階、減少動態、純手把皆可完成一場。

K．**教學**：五角形與例外倍率負擔高 → 三關分教剋制、位置、落子承諾；失敗直接重擺並提示一個原因 → **P1／M5提前** → 8/10新人五分鐘內獨立完成首場。

L．**架構效能**：20ms假設已失效；現行指紋是線性混合、漏`wp_for`等狀態 → 完整狀態固定序列化＋SHA-256；規則、數值、存檔各自版本化，原子存檔＋備份；舊重播版本不符須拒播或走相容核心。先量release熱點、減配置、分程序批跑，再評C#／GDExtension；不採「必快4倍」。官方僅支持[型別化可改善效能](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/static_typing.html) → **P0／M1** → 100案例跨平台逐tick一致；平衡552場初定≤5分鐘，達不到再評遷移。

M．**測試／CI**：30綠與單一總指紋不能涵蓋所有契約 → 私有remote、鎖引擎／模板／依賴；Windows／Linux CI逐tick比對；關鍵規則做突變測試，零測試、腳本錯誤、逾時皆失敗；平衡夜跑保存JSON、版本與錄影種子。使用[官方headless命令](https://docs.godotengine.org/en/stable/tutorials/editor/command_line_tutorial.html) → **P0／M0–M2** → 故意改壞三項待修規則都紅；不同FPS結果一致。

N．**Steam**：尚無整合實證 → 鎖[GodotSteam](https://github.com/GodotSteam/GodotSteam)版本、封裝Steam介面；先Input、Overlay、Remote Play，再成就。進度／陣型用[Auto-Cloud](https://partner.steamgames.com/doc/features/cloud)，畫質設定留本機。官方確認[本機多人標記會自動啟用RPT](https://partner.steamgames.com/doc/features/remoteplay)，仍須測控制權 → **P1／M6、M8** → 兩機邀請、斷線重連、雲端衝突、Deck休眠均通過；[Deck字高下限9px、建議12px](https://partner.steamgames.com/doc/steamhardware/compat)，本案中文仍以16px為目標。

O．**原生線上**：「確定性完成就只多一層」低估工作 → v1.1先好友房；可靠有序落子指令、房主驗合法性、規則摘要握手、斷線重連與狀態快照。採[現代Steam Networking](https://partner.steamgames.com/doc/features/multiplayer/networking)，不碰淘汰API；盲擺另做承諾／揭露 → **P3／v1.1** → 重複、亂序、丟包、版本錯誤均有明確結果；不同步能定位。

P．**行銷**：商店頁拖至M9太晚 → 授權與可讀性通過後提前頁面；10秒影片呈現「公開落子→不能反悔→殘局逆轉」。每週一片、每批邀10位小型創作者，追來源與心願單。2,000心願單不是保證；[官方也未要求demo提前半年](https://partner.steamgames.com/doc/marketing/upcoming_events/nextfest) → **P1／M4起** → demo穩定、教學通過才選Next Fest。

Q．**商業**：競品價格不能推出銷量 → US$4.99／6.99作測價方案，區域價格依[Steam定價工具](https://partner.steamgames.com/doc/store/pricing)檢查；維持無課金、無局外養成，首發先不承諾DLC。用300／1,000／3,000份作情境，非預測 → **P1／M4、M9** → 售價×區域組合扣退款、折扣、稅費與平台分成後，算損益兩平。

R．**法務**：LPC排版不能證明來源，也不能整包推定授權 → 逐檔保存作者、網址、授權版本、改作與署名。修正：依[CC BY-SA條文](https://creativecommons.org/licenses/by-sa/3.0/legalcode)，不得限制授權權利，不等於所有封裝皆違法；素材改作義務也不能直接推成整款程式須公開。[GPL素材須另判斷散布與原始形式義務](https://www.gnu.org/licenses/gpl-faq.html)。查TIPO／WIPO及目標市場近似商標，完成[Steam內容／分級問卷](https://partner.steamgames.com/doc/gettingstarted/contentsurvey)，預設不收遙測 → **P0／M0–M3** → 每項素材皆有可追溯合法依據，未知者不進公開版本。

S．**管理**：里程碑已與原型進度脫節 → 下一批重排：M0備份授權→M1三項規則與指紋→M2搜尋；並行提前M4真人試玩→M3正式素材／輸入→M5–M7內容→M8–M9。每批3–5工作日，完成首批後再估總期；列素材、音樂、Deck測試預算及20%預備。Steam每產品[US$100，另有30日與Coming Soon兩週要求](https://partner.steamgames.com/steamdirect/) → **P0** → 每批附變更摘要、證據、未解項；Claude唯一改檔、最多三輪、額度失敗不算通過；build／發佈另取當次授權。

**2．前10名優先優化**

1. 真人試玩：確認真正的「激烈」。
2. 素材授權：避免整批美術重做。
3. 修面向鎖定、衝鋒累積轉彎、反擊選人：先穩定規則。
4. 完整狀態指紋：補確定性證據。
5. 輪流落子先後手測試：驗證主模式。
6. 保留池＋萬用陣搜尋：降低過度調參。
7. 私有remote與CI：保住成果與驗收。
8. 平衡工具效能：支撐後續迭代。
9. 正式素材可讀性＋手把：確認實際遊玩成立。
10. 提前教學、demo與商店頁：開始驗證市場。

**3．最大盲點**

- 把「勝方剩26%」當成玩家感到懸念；開場可預知的互耗也會達標。
- 以純兵種矩陣代表公開輪流落子的公平性。
- 以額外剋制倍率修報表，可能增加學習負擔，卻未增加位置決策深度。
