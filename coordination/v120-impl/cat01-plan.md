# 第 1 大類：§15 前兩版精細化＋§14 驗收提速（完整細部規劃）

## A. §15 精細化

### A1（§15.1）開覆盤的基準重算背景化
- 現況：`replay_view.gd:362` `rv_base = review_run(...)` 在主執行緒同步跑一整場（最壞規則 ~7.5 秒，畫面卡住）。
- 做法：`_open_review` 先開面板、`rv_base` 設成「計算中」；用 `bg`（BgPool）開背景工作算基準，期限 20 秒、可取消；離開覆盤或陣型世代變了就 `retire`。完成才填 `rv_base`，面板的「原本」欄在算完前顯示「計算中…」，「播放如果」鈕在基準好之前可以按（如果那條本來就是背景）。headless／截圖同步做（截圖要確定性）。
- 測試：`force_async` 下開覆盤 → 立刻回來（不阻塞）、算完填入、取消後不寫。

### A2（§15.2）圖集烘焙尖峰（136 ms）
- 現況：`sprite_cache._bake_page` 用 SubViewport 畫 → `get_image()`（GPU→CPU 讀回，整頁 3072×4032）→ `_post` 再開一個 viewport 跑 shader → 再 `get_image()`。兩次大讀回就是尖峰。
- 做法（兩段）：
  1. **不讀回**：post 視窗改成常駐（`UPDATE_ONCE` 畫一次後保留），圖集直接用它的 `ViewportTexture`；painter viewport 的輸出直接當 post 的輸入（`ViewportTexture`），省掉兩次 `get_image()`。
  2. 若 Compatibility 下 ViewportTexture 有問題（例如視窗被隱藏時不保留），退回：讀回改成在「載入／標題頁閒置時」預烘（按本局常用兵種）。
- 驗收：效能模式 `atlas_sweep.worst_bake_frame_ms` 從 ~132–136 降到 < 40；ABBA 交錯比較繪圖 p95 不變；版面截圖（角色）像素差 = 0 或在誤差內（視覺回歸工具 B6）。

### A3（§15.3）掌機建議 60fps
- 掌機建議分兩顆：「掌機建議（30fps 省電）」「掌機建議（60fps）」；其餘設定一樣。字串四語。未經實機驗證照舊註明。
- 測試：PRESETS 數量、兩顆差異只在 fps_cap。

### A4（§15.4）玩家幽靈下載入口
- 現況：`SteamApi.ghost_fetch` 沒有畫面入口（死碼候選）。
- 做法：每週棋盒頁加「下載本週玩家幽靈」：沒有 Steam → 提示離線；下載中 → 「下載中…」；空結果 → 「本週還沒有玩家上傳」；有結果 → 列出前幾名（用現有幽靈軍團的卡片樣式），可挑一個對戰。全部走現有排行榜通道（單一在途），逾時照 W1 規則。
- 測試：假 Steam（FakeLB）回空、回 3 筆、逾時三種。

## B. §14 驗收提速（每項附防漏條件）

### B1（§14.1）影響分析＋同 commit 稽核
- `check.py` 的 `deps()` 現在只認 `preload("…")`；補：`load("res://…")` 字串、`.gdshader`、`data/*.json`、字串表 `strings.csv`、字型檔。動態拼字串的 `load()` 列成「未知依賴」→ 這一步每次全跑。
- 新增 `check.py --audit-selection`：同一個 commit 先跑「有快取」再跑「無快取」，逐步比對結果（通過與否、測試數、FINGERPRINT）；有任何一步「快取說通過、實跑失敗」或測試數不同 → 失敗並列出該步的依賴（要補進依賴表）。
- 防漏：未知依賴全跑；稽核在同 commit。

### B2（§14.2）測試 ID 聯集檢查
- 每個 `t_*` 步驟的日誌印出跑了哪些測試函式（`RAN <fn>`）；`check.py` 收尾時核對：所有步驟的聯集＝`run_tests.gd FILES` 全集（完整模式），而且同一個測試只在一個步驟出現。
- 防漏：漏跑、重跑都會失敗。

### B3（§14.3）模擬快取（只給「重算作者解」類）
- 先量（B9）哪些測試反覆模擬同一場；只對「驗證作者解／三星解」這種純函式重算加快取（鍵：引擎版本＋`scripts/core/**` 雜湊＋規則碼＋兩軍碼＋指令紀錄＋地圖地形＋種子）；快取值＝結果摘要（勝方、剩餘、tick、digest）。
- 防漏：確定性與金標準測試永遠實算；每次命中隨機抽 5% 重算比對，不一致就失敗；`--no-cache`（發版）停用。

### B4（§14.4）畫面狀態清冊
- `tools/screens.json`：每個截圖名 → 入口、狀態標籤（空資料、滿資料、錯誤、離線、手把、四語三字級由組合決定）。`layout_check.sh` 收尾時核對：清冊裡的每個畫面都產生了、沒有清冊外的畫面（新畫面一定要登記）。
- 受影響截圖：`LAYOUT_SHOTS=a,b` 只存指定畫面（流程照跑、只跳過存檔與檢查）→ 給開發中快速看；**每日與發版一律全量**。

### B5（§14.5）截圖平行
- `layout_check.sh` 加 `LAYOUT_JOBS=N`：各組合本來就是獨立行程，平行跑 N 個。
- 防漏：先在同一 commit 跑 1 工與 N 工，比對每組違規清單與畫面 ID 集合完全一致才把 N 設為預設；收尾核對「組合×畫面 ID」精確集合。

### B6（§14.6）視覺回歸工具
- `tools/visual_diff.py <舊> <新>`（numpy 放 `build/pylibnp`）：逐畫面算像素差比例與 SSIM（灰階、8×8 視窗），排名前 N 拼接觸表（左舊右新＋差異熱圖）；新畫面（舊沒有）全部列出。輸出 `diff.json`＋`diff_sheet_*.png`。
- 簽核：`coordination/<批次>/visual-signoff.md`（誰、看了哪些、結論）。

### B7（§14.7）美感自動檢查（第一批）
- 純黑像素：截圖中 #000～#080808 的像素比例（裝飾層也算）；**現在大量選單是黑底，先做成「警告」並出報表**，第 2 大類（桌面世界）做完後改成「違規」。
- 灰階對比：戰鬥截圖用探針登記的單位框，算單位框內平均明度 vs 框外一圈棋盤，差 < 30% 警告。
- 角度表、焦點對比階梯：等元件庫 2.0（第 2 大類）有裝飾層登記再加。

### B8（§14.8）效能 ABBA 自動化
- `tools/perf_ab.sh <A 的 game 資料夾> <B 的 game 資料夾> <輪數>`：照 ABBA 順序跑效能模式（絕對路徑輸出），收集每次 p50／p95／p99、GPU p95、atlas 尖峰，輸出成對差、標準差、結論（差 < 2 個標準差＝雜訊內）。
