從體驗與視覺節奏來看，這版大幅砍掉了致命的 7 秒凍結，架構方向正確；但在「體感微卡頓」、「資訊可讀性」與「工具量測維度」上仍有幾處硬傷需要收斂。以下為體驗與美術端的審查意見：

---

### 一、 體驗與文案檢視

1. **覆盤開局（項目 1）：**
   - **體驗**：打開不再卡死值得肯定。但若運算仍需數秒，「計算中…」純文字會讓玩家誤以為介面壞掉。建議補上微脈衝動畫或走馬燈進度，且「重算」按鈕置灰時應有 Tooltip 提示「正在計算前次結果」。
   - **文案**：「原本那一場」過於口語，破壞策略遊戲沉浸感，建議改為**「原始對局」**或**「基準戰局」**；「計算中…」建議改為**「推演戰局中…」**。

2. **烘焙 78 ms 卡頓（項目 2）：**
   - **體驗**：78 ms 在 60fps 下相當於連續丟失 4～5 幀。玩家點下「開戰」是情緒最高點，此時產生頓挫非常致命。既然整頁讀回短期內壓不進 40 ms，**體驗上必須用視覺轉場（如「開戰」布幕微動效、字卡淡入）將這 78 ms 遮掩在轉場過渡中**，絕不能直接裸露在操作響應上。

3. **操作設定頁（項目 3）：**
   - **體驗**：為了一個幀率差異並列兩顆長按鈕，會破壞設定頁的視覺階層。建議收斂為單一按鈕**「套用掌機配置」**，下方搭配一個簡單的「[30fps 省電] / [60fps 流暢]」二選一 Segmented Control。

4. **每週幽靈面板（項目 4）：**
   - **體驗**：僅顯示「花費 X 金・Y 隻」極度乾癟，玩家像在抽盲盒，無法產生「挑戰特定陣型」的策略興奮感。
   - **文案**：「沒有連上 Steam：玩家幽靈要連線才能下載。」語氣僵硬且暴露技術詞彙，建議改為**「未連線至 Steam：需保持連線以獲取每週幽靈。」**。

---

### 二、 美感報表門檻與量法重訂

1. **純黑像素比例（目前 87 張 > 1%，最高 85.8%）：**
   - **問題**：此數值顯然將「載入轉場黑幕」與「超寬螢幕黑邊（Letterbox）」誤算進去。
   - **量法修正**：建立排除名單，僅擷取「遊戲核心可操作畫面」的有效視窗區域（剔除 Loading、切幕動畫與外圍 Letterbox）。
   - **門檻建議**：正常 UI 底色應為質感深灰（如 `#0F1115`），非純黑。可操作畫面純黑（`#000000`）佔比門檻應定為 **≤ 3%**，超過即視為「底圖死黑」或「材質遺失」發出警告。

2. **棋子灰階對比度（620 隻全軍覆沒）：**
   - **問題**：以整隻精靈圖算全域對比是錯誤量法，忽略了棋盤本身的明暗格與外描邊。
   - **量法修正**：改採 **WCAG 2.1 UI 元件邊界對比度量法**。以棋子外輪廓（外緣 2~3 px）分別對比「深色棋盤格」與「淺色棋盤格」的平均亮度差（Michelson 對比度）。
   - **門檻建議**：棋子邊緣（或描邊）與兩種格子的相對亮度比需達到 **≥ 3:1**，確保在任何底格上都不會被吃掉輪廓。

---

### 三、 下一大類（元件庫、材質、字級表）前最在意的 3 件事

1. **掌機 7 吋螢幕的字級與破版相容性**：字級放大 125% 後，緊湊型面板（如幽靈清單、覆盤數值欄）是否會產生文字截斷或難看的折行。
2. **控制器焦點（Focus State）與動態反饋規範**：元件庫必須先確立「選取框 / 懸停 / 禁用態 / 載入態」的統一視覺語言，避免覆盤按鈕與幽靈列表各吹各的調。
3. **材質 Atlas 記憶體預算與串流規則**：開戰烘焙 78ms 已逼近極限，擴充材質庫前若未規範貼圖上限與非同步加載管線，後續卡頓問題將呈倍數惡化。

---

### 四、 最多 4 條必改清單

1. **烘焙微卡頓視覺遮罩**：開戰前的 78 ms 烘焙延遲，必須以開戰 UI 動效（如進場橫幅/轉場淡入）掩蓋，消滅操作裸卡感。
2. **覆盤與幽靈文案潤飾**：「原本那一場」改為「原始對局」；連線錯誤提示修飾為「未連線至 Steam：需保持連線以獲取每週幽靈。」。
3. **幽靈面板資訊增強**：對戰清單不能只列金幣與數量，必須補上該陣型「核心棋子頭像（至少 3 隻）」或「主要羈絆標籤」。
4. **掌機預設按鈕整併**：操作頁取消並列兩顆長按鈕，改為單一「套用掌機配置」按鈕，並於其下以次級開關切換 30fps/60fps。

結論：有條件
