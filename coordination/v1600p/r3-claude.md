# R3｜主持人 Claude：S4、S6 主筆；S2、S5、S7、S9 查核要點

## S4 尖峰幀看得懂（P3）
1. **核心問題**：在 34～41 隻混戰的尖峰幀，玩家 3 秒內能不能說出「誰在推進、我跟的那隻在打誰」，而且新加的東西不增加對兵的遮擋？
2. **範圍**：①「勢」箭頭：每隊一條，起點＝該隊前線（最靠中線的 1/4 兵平均 x）、方向＝前線 2 秒內位移；只在交戰中顯示、粗 6px、靛藍／朱紅＋形狀（色盲：▶ 與 ▷）。②自動焦點：沒手動跟拍時，每 3 秒挑「最近一次擊倒或最高傷害的一對」當焦點（沿用 `pick_focus` 的畫法），手動跟拍優先、倒帶不補。③跳字避讓：短標生成時查周圍 8 格兵密度，往空處偏移，鎖在盤內 ≥12px。**不做**：導播鏡位 2.0、外圍退色（P1）。
3. **模組**：`scripts/ui/battle/battle_units.gd`（`pick_focus`、`_draw_focus_halo`、`_draw_focus_marks`）、`scripts/ui/battle/battle_fx.gd`（`_fx_text`、`_bubble`）、`scripts/ui/battle_view.gd`（`_update_action_focus`、事件迴圈）；勢的計算放純函式（新檔 `scripts/game/front_line.gd`）。前置：無（1.5.0 已有焦點與記號）。
4. **工作量**：3～5 人日；前提：勢只用展示快照（不進模擬）；信心中。
5. **固定場景**：`v150_03f_battle_focus`（tick 150、34 隻）、`18_battle_new`（tick 170、36 隻）、`87d_boss_battle`（tick 260、41 隻），固定時鐘、1280×800、zoom 1.0；對照＝左 1.5｜中切片｜右切片灰階；四層觀片①③。
6. **判決**：Go＝固定時鐘低對比棋子不超過基線容差、三張尖峰幀「新增元素蓋兵臉／胸」像素 0、跳字裁切 0；真人（5 人，看三張圖 3 秒）各答「誰在推進」≥4/5 正確。No-Go＝任一條不過。資料不足＝真人沒做（只能出工程判決，畫面判讀標待驗）。
7. **No-Go 退路**：保留跳字避讓（獨立有價值）；勢箭頭改成只在戰力條上顯示推進方向（盤外）；自動焦點關掉、保留手動跟拍。
8. **量產**：其他 24 張戰鬥畫面跑固定時鐘；設定加「勢箭頭」開關（簡化介面預設關）；下一道門檻＝輸入矩陣擴充（自動焦點不吃輸入，但手動跟拍搶權要測）。

## S6 一個完整玩法循環：塔分岔＋完整續塔（P7）
1. **核心問題**：每 3 層一次「契約路線／休整」選擇，能不能讓熟手在同一座塔走出不同後續，而且開局→選路→結算→續玩→重啟不重抽、舊存檔不壞？
2. **範圍**：第 3、6、9…層後出現分岔卡（2 條：契約＝下 3 層加一種既有突變、獎勵多一枚印；休整＝下 3 層照常、可重排陣型）；路線只由「塔種子＋已選序列」決定；新 run 存陣型、規則碼、路線序列、待結算 ID。**不做**：聯賽、棋譜集、桌面路線圖美術（P1 之後）。
3. **模組**：`scripts/game/tower.gd`（`spec`、`make_rules`、`next_run`、`sanitize_run`）、`scripts/game/save.gd:187`（`tower_run` 遷移）、`scripts/ui/screens/game_v16.gd:2538～2572`（續局、結算）；新欄位 `tower_route`（陣列）、`tower_run_v2`（字典）。前置：P11 的存檔遷移測試範本。
4. **工作量**：4～6 人日；前提：契約只重組既有規則（不升 `RULES_VERSION`）；信心中高。
5. **固定場景**：種子 1601001、選擇序列〔契約、休整、契約〕；畫面：遠征頁塔卡（`en-104`、`v140` 塔截圖）、分岔卡新截圖兩張（契約選中／休整選中），24 組。
6. **判決**：Go＝同種子同序列兩台機器路線雜湊相同；每階段中斷重啟後路線不變、獎勵只結算一次；舊整數 `tower_run` 讀進來照舊路線（不猜歷史）；分岔卡 R14 ≤6、英文 150% 不裁切；熟手 5 人有 ≥3 人兩次選了不同路線並說得出理由。No-Go＝重抽、重領或舊進度遺失任一出現。資料不足＝真人沒做。
7. **No-Go 退路**：回固定塔（1.4.0），保留新 run 欄位但不讀；已驗的路線資料留給下一版。
8. **量產**：塔圖美術（P1 主光與材質之後）、更多契約種類；下一道門檻＝平衡（各路線勝率 20 局抽樣不偏離 ±15%）。
