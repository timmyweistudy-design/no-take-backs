# V1.4.0 裁決紀錄
- 方案 docs/history/2026-11-08-v1.4.0-plan.md；方向候選 docs/history/2026-11-08-v1.4.0-directions.md（v140-r1、r2）。使用者：每一項都完整規劃、全做。
## 第一批（#1 時光機、#3 契約、#2 宿敵；審查 coordination/v140-i1）
- Codex 必修全修：契約存檔欄位與上限、代價不可繞過（修剪超額陣型）、每戰結束結算契約（含輸與第 7 站）、覆盤淡圈回原局要清、分岔 tick +1、和局不算被打敗、宿敵再贏加在原紀錄、宿敵增援守兵種上限。
- Antigravity 美化全採用：米白粉筆虛線圈、分岔線貫穿兩圖、覆盤兩顆按鈕同列、拿掉格子座標、契約羊皮紙籤＋火漆章、「不簽」次要樣式、宿敵木牌、雪恥印章、時光機羊皮紙按鈕。
- Ruling B1：宿敵只在遠征（格子模式）— 遠征是格子陣型，存 (兵種, 欄, 列) 就能重現；自由陣型與地圖變體不收 — 代價：其他模式輸了不會記宿敵。
- Ruling B2：契約獎勵是「永久」加成（和事件一樣）— 契約有代價與風險，報酬要夠吸引 — 代價：遠征後段可能比以前強；存檔上限放寬到 220 金／40 隻。
- Ruling B3：時光機的原本時間線用第二份模擬同步跑（每 tick 多一次 step），不預錄位置 — 確定性保證同 tick 同狀態；成本只在覆盤播放時 — 代價：跳回很前面時要重追。

## 第二批（#5 接力、#6 最小成本、#14 戰報卡／GIF、#16 遊戲間、#8 指揮官；審查 coordination/v140-i2）
- Codex 必修全修：輪抽 AI 用自己的卡池、競猜結果行在報告重建後才寫、離開就取消押注、指揮官預算改成「基礎＋自己加成」（明確記選誰）、GIF 執行緒退出時等寫完、重播碼不印在卡上改按鈕複製；建議也修：錄影中開別的畫面就取消、存圖檢查回傳值與檔名加毫秒。

static var _digest := ""

## 數值摘要：本檔所有常數的 SHA-256 前 16 碼。遊戲、AI、平衡工具、重播都記錄它，證明跑的是同一份數值。
static func data_digest() -> String:
	if _digest == "":
		var m: Dictionary = load("res://scripts/core/unit_defs.gd").get_script_constant_map()
		# 常數名稱是 StringName，直接排序是比記憶體位址、不是字母順序 → 先轉成 String 再排
		var pairs: Array = []
		for k in m:
			pairs.append([String(k), m[k]])
		pairs.sort_custom(func(a, b): return a[0] < b[0])
		var txt := ""
		for pr in pairs:
			txt += "%s=%s;" % [pr[0], var_to_str(pr[1])]
		_digest = txt.sha256_text().substr(0, 16)
	return _digest

## 每種兵一格的 0 陣列（取代到處寫死的 [0, 0, 0, 0, 0]）。
static func zeros() -> Array:
	var a: Array = []
	a.resize(total())
	a.fill(0)
	return a

# 落子無悔 V1.4.0 實作方案：18 個方向全做（進度見 §3）

## 0. 共同原則

## 2. 各項細節

### #1 戰術時光機／一子之差
- **現況**：輸了以後的「覆盤」已經可以改一隻兵、重算、比較兩條走勢、播放「如果」。
- **新增**
  - 重播暫停時出現「時光機：回到開戰前改一隻兵」，直接進覆盤。
  - 覆盤算出兩條時間線第一次不一樣的那一秒，在兩張走勢圖上畫分岔記號，並寫出「第 N 秒開始分岔」。
  - 播放「如果」時從分岔前 2 秒開始；原本那條時間線同步在跑，兵的位置畫成地上的白圈（隊伍色小點）。看得出哪裡開始不一樣。
- **規則碼**：不動（覆盤本來就只看不算）。
- **驗收**：分岔計算與時間線同步的測試；覆盤截圖兩語三字級。

### #3 戰利品契約
- 遠征每戰前多一個選項「簽契約」，從 3 份抽出的契約選 0～1 份。
  - 例如：不准帶遠程、只能帶 N 種兵、要在 45 秒內打完、我方少 10 金。
  - 達成就拿額外報酬：多一次事件三選一，或下一戰多 10 金。
- 判定只看戰前配置與戰後狀態，不改模擬（和殘局目標同一套判定）。
- 介面：在遠征的戰前節點下方放一張羊皮紙契約卡，打勾簽名；結果頁顯示「契約達成／失敗」。

### #2 宿敵戰記
- 遠征裡打敗你的那個敵陣會被記成「宿敵」：取一個稱號（例如「雙橋的長槍牆」），存它的陣型、規則與你輸的次數。
- 之後的遠征有機率在菁英節點遇到它：它會強化（+10 金、AI 高一級），開戰前有一張宿敵卡。
- 打贏就是「復仇」，寫進戰績頁的戰記。
- 不改模擬：宿敵就是存下來的敵陣＋既有的遠征加成參數。

### #4 軍令連鎖

- 沿用既有的手動技能與定時施放紀錄（第 9 章已有腳本），規則碼已存在。

| 試玩紀錄 | 關／開；關 | 延續現有功能，說明記錄欄位與位置 | 顯 |
| 清除資料 | 分類選擇後確認；手動 | 分別清除快取、重播、紀錄或全部進度 | 顯 |

Steam Cloud 顯示同步範圍與狀態；若由平台控制，提供說明與入口，不做無法真正控制的平台開關。現有「進度同步、裝置設定留本機」原則可延續。

**設定資料設計**

每個設定定義統一登記：

```text
穩定 ID／分類／資料型別／合法值／預設值
作用範圍／生效時機／搜尋詞／說明
相依條件／預設組歸屬／版本遷移方式
```

- 裝置設定：解析度、效能、輸入、音量，留本機。
- 個人偏好：字級、提示、收藏，可匯出。
- 規則預設：獨立版本與規則碼。
- 進行中對局：凍結規則，不跟著全域偏好改動。
- 舊版 `reduce_fx` 等複合開關遷移成新值時，保留原本降低動態的效果。

**C．角色：投射物、握持、轉身、圖鑑與共同驗收**

**C1．遠程演出：統一從發射到命中的時間關係**

每次攻擊建立可辨識的演出紀錄：

```text
攻擊識別
→ 前搖
→ 離手／離弦
→ 飛行或連結
→ 命中
→ 血條、狀態、受擊、聲音
→ 收招
```

飛行物不能再由「扣血事件發生後」才啟動。角色手上的物件與飛行物必須共用發射錨點，交接時只存在一份。

| 兵種／效果 | 形狀與發射準備 | 飛行與軌跡建議 | 命中表現 |
|---|---|---|---|
| 弓箭手 | 木桿、金屬箭頭、羽尾；前搖先搭箭，箭尾跟弦移動 | 淺拋物線；被動觀戰約 0.15～0.30 秒 | 箭尖抵達才扣血；盾面短火花、肉身短停留，材質音不同 |
| 投彈兵 | 清楚的火罐／黑色彈體、短引信；甩手時離手 | 高拋物線約 0.25～0.40 秒；以距離調整弧高 | 落點爆裂，主目標與波及共用一次爆炸，避免每個受害者再炸一顆 |
| 骷髏法師普攻 | 書頁紫火聚成帶尾焰的火種 | 低弧／近直線約 0.15～0.30 秒 | 紫色小爆散與骨屑；避免整片白閃 |
| 孢子菇 | 傘緣吐出淡綠孢子，有來源與擴散方向 | 孢子向毒圈內飄散，單粒壽命約 0.3～0.6 秒；不代表單粒傷害 | 實際毒傷 tick 時目標出現小毒標與短促反應 |
| 醫者 | 杖頂十字聚光 | 保留治療弧線，約 0.10～0.20 秒 | 抵達時增加血量、出現十字；不能像攻擊爆炸 |
| 巫毒娃娃 | 扎針動作、針頭與線端可辨識 | 保留綁定線，傷害時約 0.10 秒脈衝沿線傳遞 | 目標同步抽動；不是可躲避的飛針 |
| 鼓手 | 鼓槌接觸鼓面 | 短距離聲波圈約 0.2 秒 | 表示鼓舞，不畫成傷害彈 |
| 吸塵貓 | 吸口與目標間有氣流方向 | 流線朝吸口移動，跟既有拉動期間一致 | 不額外創造撞擊或飛行傷害 |
| 沙漏精靈 | 沙粒向沙漏聚集、施法前兆 | 效果範圍內沙粒／刻度波紋 | 對齊既有時停事件，不偽裝成單體彈 |
| 法師召喚 | 書頁符號連到合法屍體位置 | 短暫符線、骨片由地面組起 | 和普攻紫火明確區別 |

爆爆羊是本體接觸／死亡爆炸，小石魔是拍地效果，皆不新增憑空飛出的遠程武器。

**時間同步的實作選擇**

上述較長飛行時間**超過目前 0.1 秒展示緩衝**，不能只改特效長度。

建議分兩條：

- **純自動對決、重播、圖鑑真模擬**：展示緩衝擴至約 8～10 tick，容納前搖與飛行；血條、死亡、音效、戰報事件一起使用展示時間。
- **有即時手動軍令的對局**：先維持短緩衝，使用約 0.05～0.10 秒快速飛行。不能直接把長緩衝套上去，增加操作延遲。
- 若要求手動軍令也有完整長飛行，應另設真正的發射／命中模擬事件，明確決定追蹤、失去目標、飛行中死亡等規則；這屬於**新戰鬥規則版本**，列為可做。

共同限制：

- 使用展示 tick 與插值，不用彼此獨立的牆鐘計時器。
- 飛行終點取實際命中時的目標位置；保留足夠快照，不能只查目前畫面位置。
- 暫停時飛行停住，倍速時同步加速，跳轉後清除並重建。
- 第一擊缺少完整前置時間時縮短演出，不在開戰前憑空飛彈。
- 同一發炸彈的波及事件不能生成多顆彈。
- 減少特效仍保留物件本體、路徑方向及必要命中提示。

**C2．手持物：建立共同握持畫法**

現在的「像被裁掉」至少有三個不同來源：物件本身沒畫完整、手部遮擋順序不對、圖鑑構圖越界。應分別修。

**共同部件**

- 武器局部座標包含：握點、柄尾、護手、刃根／工具根、尖端、發射點。
- 手分成掌後片與手指前片。
- 一般順序：遠手／掌後 → 握柄 → 掌前與手指 → 護手、刃身；實際順序由角度調整。
- 手指以少量弧線與指節塊面包住柄，不需要寫實五指。
- 握柄被手蓋住的部分合理隱藏，但柄尾、護手與刃根要讓人能判讀連接。

**逐類修正**

- 劍士：補柄尾、握柄、護手，避免刀刃直接插進掌心。
- 刺客：兩把短刀分別有握點；遠手與近手不能共用固定最前層。
- 騎兵／長槍兵：槍桿在握點分前後段，手指覆在桿前；刺擊時手與槍一起移動。
- 弓箭手：弓把、握弓手、拉弦手、箭與弦各自有錨點，拉弦時不能脫離。
- 投彈兵：火罐在離手前跟手，離手後從手部層移除。
- 醫者：手包住杖身，十字與杖頂不隨轉身穿頭。
- 鼓手：鼓槌有短柄尾；敲擊終點落在鼓面。
- 狂戰士：兩柄斧的斧頭、柄與手分離，側身時遠斧可被身體遮住。
- 法師：手托住書脊／底邊，書頁朝向與胸部朝向一致。
- 巫毒娃娃與骷髏：針、骨製工具也走同一握持規則。

驗收包括待機、前搖、命中、收招與各方向，不能只修正面待機圖。

**C3．轉身：用程式部件做有厚度的多角度角色**

建議採用 **8 個主要方向＋角度間部件插值**。保留程式繪製，完成後可烘焙圖集。

不再使用整隻角色水平壓縮至 0.3 的方式。

**角色分層**

```text
底座與接地陰影
遠側腳／遠側手／遠側持物
後腦、頭盔後片、披風、背部配件
軀幹與頭部主體
臉部
近側腳／近側手／近側持物
必要前景裝飾
```

**轉向規則**

- 頭部保持體積，只允許少量輪廓變化。
- 臉部中心隨角度沿頭部橢圓移動；遠眼逐漸變窄、被輪廓遮住。
- 側面加入鼻部／口部小輪廓，背面不畫眼睛。
- 帽沿、頭盔護頰、盾邊、書厚度有側面專屬幾何。
- 肩、手、腳及持物依近遠側錯開，轉過側面時交換前後層。
- 軀幹先轉、頭略提早看向目標，武器稍後跟上；差距保持短，避免像零件散開。
- 步行轉向保留步相與腳底位置，不能在換角度時滑動。
- 裝備左右手歸屬固定；完整旋轉不等於整張鏡像翻面。

**不同輪廓族群**

| 類型 | 需要專屬處理 |
|---|---|
| 人形兵 | 共用頭、肩、手腳的角度骨架，各自加帽與武器 |
| 騎兵 | 人、馬、長槍分開轉；馬頭與身體有側面長度 |
| 蘑菇／史萊姆 | 外形保持體積，臉、斑點、冠飾繞體移動 |
| 寶箱怪 | 蓋板、箱體、鉸鏈、牙與舌頭有前後厚度 |
| 幽靈 | 臉跟著轉，尾部與雙手錯動 |
| 娃娃 | 球頭、鈕扣眼、縫線與針方向一致 |
| 沙漏精靈 | 框架、玻璃、翅片分層，側面仍有框厚 |
| 吸塵貓 | 耳、背包、吸管與口部不可一起壓扁 |
| 石魔 | 肩甲、拳、軀幹有側面面積與遮擋 |

先以**劍士、弓箭手、騎兵、寶箱怪、史萊姆、法師**六種驗證方法，再展開其餘兵種。

Godot 的自訂繪製與繪製變換可支援這種部件式方案；無須先改用外部角色工具。[Godot 4.6 文件](https://docs.godotengine.org/en/4.6/tutorials/2d/custom_drawing_in_2d.html)

容量先不設否決門檻，但要量測：

- 各方向圖集佔用、冷啟動、首次進圖鑑及換塗裝時間。
- 圖鑑高解析預覽與戰場快取分開。
- 分頁／按需產生，避免所有兵種、方向、塗裝全部同步常駐。
- 快取與直接繪製必須有同角度比較表，不能兩套畫法越改越不同。

**C4．圖鑑大圖：固定名稱區，角色使用完整動作包絡**

建議卡片分區：

```text
┌──────────────────────────────┐
│ 名稱、定位、費用              │ 固定標題區
├──────────────────────────────┤
│                              │
│     棋子完整展示區            │ 角色與持物都在此區
│                              │
│ 旋轉／動作／播放／逐格         │
├──────────────────────────────┤
│ 數值、技能、克制與被克制       │
└──────────────────────────────┘
```

- 對每兵種計算所有方向、待機與攻擊姿勢的聯集邊界。
- 以聯集邊界選定固定縮放，不在每一幀忽大忽小。
- 長槍、旗、火罐前搖也計入邊界，不能只算身體。
- 預留約 10% 安全邊；需要時加大展示區，不把整隻縮到難辨識。
- 底座位置穩定；標題區與角色區不能互相侵入。
- 「完整棋子」與「近看細節」兩種視圖；近看可平移，完整視圖一鍵復原。
- 攻擊展示預留目標假人與飛行區，不讓箭飛進名稱或說明。
- 法師普攻、召喚，投彈兵投彈、貼身敲擊等，要能分別選擇。
- 小劇場保留真模擬，不能只靠擺姿勢驗收攻擊。

**C5．共同驗收：每種兵都有可逐格核對的證據**

每次檢查包標明版本、兵種 ID、角度、狀態、規則碼與種子，輸出：

1. **360 度影片／GIF**
   - 每兵種 4～6 秒，完整一圈。
   - 正常速度與慢速各一份。
   - 附 16 個角度的靜態拼表，用來檢查側面與遮擋。

2. **持物細節表**
   - 握點、護手、柄尾放大。
   - 前後左右與攻擊關鍵姿勢。
   - 同時提供原尺寸，確認縮小後仍看得懂。

3. **攻擊逐格表**
   - 前搖、離手、飛行中點、命中前、命中、收招。
   - 標出展示 tick、傷害 tick、HP 前後值與音效時點。
   - 不以 GIF 作為唯一精確驗收資料，另附影片與逐格圖。

4. **圖鑑版面表**
   - 四語、三個既有字級。
   - 完整動作包絡與名稱區疊圖。
   - 若新增 175%，獨立增加一組。

5. **真戰鬥案例**
   - 遠程近距離與最遠距離、移動目標、盾兵。
   - 施放者同 tick 死亡、目標死亡、多發同點爆炸。
   - 暫停、倍速、倒回、跳轉、減少特效與色盲模式。

共同確認表：

| 兵種 | 轉身 | 握持／部件 | 攻擊同步 | 圖鑑構圖 | 結論 |
|---|---|---|---|---|---|
| 每種一列 | 通過／問題編號 | 通過／不適用／問題編號 | 通過／問題編號 | 通過／問題編號 | 待修／待複核／通過 |

使用者可以回覆「騎兵 135° 槍桿穿手」，我們能直接重現，不必重新描述整段動畫。

**D．V1.4 基礎上需要完成的大項**

**D1．大廳重整：先選玩法，再看條件，再擺陣｜必做**

承接 V1.4 裁決 B23、B25：

- 頂部只顯示模式、雙方、規則摘要與續局狀態。
- 左側顯示本戰條件，中央棋盤，底部兵種卡，右側選取兵種說明。
- `Beats／Fears` 改成完整本地化的克制／被克制區，不擠在擺陣頂欄。
- 進階七類規則收進抽屜式編輯器，主畫面只顯示與標準不同之處。
- 契約、貼紙、巨獸、宿敵的效果先摘要；選取可展開詳細條件。
- 非法陣型直接標出哪隻兵、哪個條件，提供定位。
- 開戰是唯一主要動作；清空、載入、匯入降低視覺權重。
- 設定頁開關與規則編輯器使用同一套控件行為。

**D2．結果頁重整：讓玩家知道下一步與發生原因｜必做**

承接 V1.4 裁決 B25：

- 第一層：勝負、耗時、剩餘戰力、關卡／契約達成狀態。
- 主要按鈕依模式變成下一站、下一局或再試一次。
- 第二層：重播、時光機、統計。
- 分享卡、GIF、出題、接力收到「分享與工坊」。
- 損失原因使用可查證事件，例如「第 24 秒右路失守」，點擊跳到重播。
- 不把相關性寫成因果；無法證明時顯示事件描述。
- 競猜明示原先選擇、實際勝負、差距與得分公式。
- 車輪戰明示留下哪些殘兵；雙封蠟顯示三封總結果。

**D3．大量混戰：整理地面、棋子、飛行物與事件層級｜必做**

- 地面先畫範圍與機關；角色依腳點排序；空中飛行物按高度及必要遮擋處理。
- 機關預警、時停、衝鋒／破陣等關鍵訊息高於普攻裝飾。
- 飄字在短時間窗合併，治療與傷害分流，重要狀態不合併掉。
- 同類爆炸保留各自實際位置，減少的是煙塵與殘片。
- 選取單位顯示目標、狀態及受遮擋輪廓。
- 事件列可篩選隊伍與事件類型，點擊定位／跳重播。
- 簡化模式保留敵我、傷害來源與危險區域。

這符合 Riot 對特效層級、輪廓與減少雜訊的設計原則；此處是對本作的具體套用。[Riot 原文](https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/)

**D4．新玩法平衡與流程補完｜該做**

不再只看隨機陣型總勝率。

- 巨獸：近戰斷臂路線、純遠程、混編、廉價大量兵分開驗證。
- 車輪戰：殘兵累積是否滾雪球、支援兵是否過強、最低預算補正是否可利用。
- 輪抽：先後手、卡池組合、AI 選卡與實際可部署性。
- 雙封蠟：先封／後封、平手、交接資訊是否洩漏。
- 遠征：契約永久加成、貼紙、事件獎勵的疊加上限與強勢組合。
- 每週棋盒：題目種子、卡池、對手與規則摘要固定保存。
- 幽靈軍團：保留既有 ID；修改內容另開版本，不能讓已通關 ID 指向另一陣型。
- 測試使用鏡像換邊、固定代表陣、隨機陣與刻意尋找漏洞的陣型。
- 先建立基準，再決定調數值；任何改戰鬥的調整都走版本與規則碼。

**D5．資料、代碼與重播生命週期｜必做**

- 匯入先預覽類型、版本、模式、規則差異與合法性。
- 對損毀、過長、未知欄位、不合法兵種、越界位置提供明確錯誤。
- 舊重播支援時使用對應規則；不支援時明示，不能用新版偷偷重算。
- 分享檔標示遊戲版本、規則版本、數值摘要。
- 設定、規則、進度各自遷移與備份。

**C1．遠程演出：統一從發射到命中的時間關係**

每次攻擊建立可辨識的演出紀錄：

```text
攻擊識別
→ 前搖
→ 離手／離弦
→ 飛行或連結
→ 命中
→ 血條、狀態、受擊、聲音
→ 收招
```

飛行物不能再由「扣血事件發生後」才啟動。角色手上的物件與飛行物必須共用發射錨點，交接時只存在一份。

| 兵種／效果 | 形狀與發射準備 | 飛行與軌跡建議 | 命中表現 |
|---|---|---|---|
| 弓箭手 | 木桿、金屬箭頭、羽尾；前搖先搭箭，箭尾跟弦移動 | 淺拋物線；被動觀戰約 0.15～0.30 秒 | 箭尖抵達才扣血；盾面短火花、肉身短停留，材質音不同 |
| 投彈兵 | 清楚的火罐／黑色彈體、短引信；甩手時離手 | 高拋物線約 0.25～0.40 秒；以距離調整弧高 | 落點爆裂，主目標與波及共用一次爆炸，避免每個受害者再炸一顆 |
| 骷髏法師普攻 | 書頁紫火聚成帶尾焰的火種 | 低弧／近直線約 0.15～0.30 秒 | 紫色小爆散與骨屑；避免整片白閃 |
| 孢子菇 | 傘緣吐出淡綠孢子，有來源與擴散方向 | 孢子向毒圈內飄散，單粒壽命約 0.3～0.6 秒；不代表單粒傷害 | 實際毒傷 tick 時目標出現小毒標與短促反應 |
| 醫者 | 杖頂十字聚光 | 保留治療弧線，約 0.10～0.20 秒 | 抵達時增加血量、出現十字；不能像攻擊爆炸 |
| 巫毒娃娃 | 扎針動作、針頭與線端可辨識 | 保留綁定線，傷害時約 0.10 秒脈衝沿線傳遞 | 目標同步抽動；不是可躲避的飛針 |
| 鼓手 | 鼓槌接觸鼓面 | 短距離聲波圈約 0.2 秒 | 表示鼓舞，不畫成傷害彈 |
| 吸塵貓 | 吸口與目標間有氣流方向 | 流線朝吸口移動，跟既有拉動期間一致 | 不額外創造撞擊或飛行傷害 |
| 沙漏精靈 | 沙粒向沙漏聚集、施法前兆 | 效果範圍內沙粒／刻度波紋 | 對齊既有時停事件，不偽裝成單體彈 |
| 法師召喚 | 書頁符號連到合法屍體位置 | 短暫符線、骨片由地面組起 | 和普攻紫火明確區別 |

爆爆羊是本體接觸／死亡爆炸，小石魔是拍地效果，皆不新增憑空飛出的遠程武器。

**時間同步的實作選擇**

上述較長飛行時間**超過目前 0.1 秒展示緩衝**，不能只改特效長度。

建議分兩條：

- **純自動對決、重播、圖鑑真模擬**：展示緩衝擴至約 8～10 tick，容納前搖與飛行；血條、死亡、音效、戰報事件一起使用展示時間。
- **有即時手動軍令的對局**：先維持短緩衝，使用約 0.05～0.10 秒快速飛行。不能直接把長緩衝套上去，增加操作延遲。
- 若要求手動軍令也有完整長飛行，應另設真正的發射／命中模擬事件，明確決定追蹤、失去目標、飛行中死亡等規則；這屬於**新戰鬥規則版本**，列為可做。

共同限制：

- 使用展示 tick 與插值，不用彼此獨立的牆鐘計時器。
- 飛行終點取實際命中時的目標位置；保留足夠快照，不能只查目前畫面位置。
- 暫停時飛行停住，倍速時同步加速，跳轉後清除並重建。
- 第一擊缺少完整前置時間時縮短演出，不在開戰前憑空飛彈。
- 同一發炸彈的波及事件不能生成多顆彈。
- 減少特效仍保留物件本體、路徑方向及必要命中提示。

**C2．手持物：建立共同握持畫法**

現在的「像被裁掉」至少有三個不同來源：物件本身沒畫完整、手部遮擋順序不對、圖鑑構圖越界。應分別修。

**共同部件**

- 武器局部座標包含：握點、柄尾、護手、刃根／工具根、尖端、發射點。
- 手分成掌後片與手指前片。
- 一般順序：遠手／掌後 → 握柄 → 掌前與手指 → 護手、刃身；實際順序由角度調整。
- 手指以少量弧線與指節塊面包住柄，不需要寫實五指。
- 握柄被手蓋住的部分合理隱藏，但柄尾、護手與刃根要讓人能判讀連接。

**逐類修正**

- 劍士：補柄尾、握柄、護手，避免刀刃直接插進掌心。
- 刺客：兩把短刀分別有握點；遠手與近手不能共用固定最前層。
- 騎兵／長槍兵：槍桿在握點分前後段，手指覆在桿前；刺擊時手與槍一起移動。
- 弓箭手：弓把、握弓手、拉弦手、箭與弦各自有錨點，拉弦時不能脫離。
- 投彈兵：火罐在離手前跟手，離手後從手部層移除。
- 醫者：手包住杖身，十字與杖頂不隨轉身穿頭。
- 鼓手：鼓槌有短柄尾；敲擊終點落在鼓面。
- 狂戰士：兩柄斧的斧頭、柄與手分離，側身時遠斧可被身體遮住。
- 法師：手托住書脊／底邊，書頁朝向與胸部朝向一致。
- 巫毒娃娃與骷髏：針、骨製工具也走同一握持規則。

驗收包括待機、前搖、命中、收招與各方向，不能只修正面待機圖。

**C3．轉身：用程式部件做有厚度的多角度角色**

建議採用 **8 個主要方向＋角度間部件插值**。保留程式繪製，完成後可烘焙圖集。

不再使用整隻角色水平壓縮至 0.3 的方式。

**角色分層**

```text
底座與接地陰影
遠側腳／遠側手／遠側持物
後腦、頭盔後片、披風、背部配件
軀幹與頭部主體
臉部
近側腳／近側手／近側持物
必要前景裝飾
```

**轉向規則**

- 頭部保持體積，只允許少量輪廓變化。
- 臉部中心隨角度沿頭部橢圓移動；遠眼逐漸變窄、被輪廓遮住。
- 側面加入鼻部／口部小輪廓，背面不畫眼睛。
- 帽沿、頭盔護頰、盾邊、書厚度有側面專屬幾何。
- 肩、手、腳及持物依近遠側錯開，轉過側面時交換前後層。
- 軀幹先轉、頭略提早看向目標，武器稍後跟上；差距保持短，避免像零件散開。
- 步行轉向保留步相與腳底位置，不能在換角度時滑動。
- 裝備左右手歸屬固定；完整旋轉不等於整張鏡像翻面。

**不同輪廓族群**

| 類型 | 需要專屬處理 |
|---|---|
| 人形兵 | 共用頭、肩、手腳的角度骨架，各自加帽與武器 |
| 騎兵 | 人、馬、長槍分開轉；馬頭與身體有側面長度 |
| 蘑菇／史萊姆 | 外形保持體積，臉、斑點、冠飾繞體移動 |
| 寶箱怪 | 蓋板、箱體、鉸鏈、牙與舌頭有前後厚度 |
| 幽靈 | 臉跟著轉，尾部與雙手錯動 |
| 娃娃 | 球頭、鈕扣眼、縫線與針方向一致 |
| 沙漏精靈 | 框架、玻璃、翅片分層，側面仍有框厚 |
| 吸塵貓 | 耳、背包、吸管與口部不可一起壓扁 |
| 石魔 | 肩甲、拳、軀幹有側面面積與遮擋 |

先以**劍士、弓箭手、騎兵、寶箱怪、史萊姆、法師**六種驗證方法，再展開其餘兵種。

Godot 的自訂繪製與繪製變換可支援這種部件式方案；無須先改用外部角色工具。[Godot 4.6 文件](https://docs.godotengine.org/en/4.6/tutorials/2d/custom_drawing_in_2d.html)

容量先不設否決門檻，但要量測：

- 各方向圖集佔用、冷啟動、首次進圖鑑及換塗裝時間。
- 圖鑑高解析預覽與戰場快取分開。
- 分頁／按需產生，避免所有兵種、方向、塗裝全部同步常駐。
- 快取與直接繪製必須有同角度比較表，不能兩套畫法越改越不同。

**C4．圖鑑大圖：固定名稱區，角色使用完整動作包絡**

建議卡片分區：

```text
┌──────────────────────────────┐
│ 名稱、定位、費用              │ 固定標題區
├──────────────────────────────┤
│                              │
│     棋子完整展示區            │ 角色與持物都在此區
│                              │
│ 旋轉／動作／播放／逐格         │
├──────────────────────────────┤
│ 數值、技能、克制與被克制       │
└──────────────────────────────┘
```

- 對每兵種計算所有方向、待機與攻擊姿勢的聯集邊界。
- 以聯集邊界選定固定縮放，不在每一幀忽大忽小。
- 長槍、旗、火罐前搖也計入邊界，不能只算身體。
- 預留約 10% 安全邊；需要時加大展示區，不把整隻縮到難辨識。
- 底座位置穩定；標題區與角色區不能互相侵入。
- 「完整棋子」與「近看細節」兩種視圖；近看可平移，完整視圖一鍵復原。
- 攻擊展示預留目標假人與飛行區，不讓箭飛進名稱或說明。
- 法師普攻、召喚，投彈兵投彈、貼身敲擊等，要能分別選擇。
- 小劇場保留真模擬，不能只靠擺姿勢驗收攻擊。

**C5．共同驗收：每種兵都有可逐格核對的證據**

每次檢查包標明版本、兵種 ID、角度、狀態、規則碼與種子，輸出：

1. **360 度影片／GIF**
   - 每兵種 4～6 秒，完整一圈。
   - 正常速度與慢速各一份。
   - 附 16 個角度的靜態拼表，用來檢查側面與遮擋。

2. **持物細節表**
   - 握點、護手、柄尾放大。
   - 前後左右與攻擊關鍵姿勢。
   - 同時提供原尺寸，確認縮小後仍看得懂。

3. **攻擊逐格表**
   - 前搖、離手、飛行中點、命中前、命中、收招。
   - 標出展示 tick、傷害 tick、HP 前後值與音效時點。
   - 不以 GIF 作為唯一精確驗收資料，另附影片與逐格圖。

4. **圖鑑版面表**
   - 四語、三個既有字級。
   - 完整動作包絡與名稱區疊圖。
   - 若新增 175%，獨立增加一組。

5. **真戰鬥案例**
   - 遠程近距離與最遠距離、移動目標、盾兵。
   - 施放者同 tick 死亡、目標死亡、多發同點爆炸。
   - 暫停、倍速、倒回、跳轉、減少特效與色盲模式。

共同確認表：

| 兵種 | 轉身 | 握持／部件 | 攻擊同步 | 圖鑑構圖 | 結論 |
|---|---|---|---|---|---|
| 每種一列 | 通過／問題編號 | 通過／不適用／問題編號 | 通過／問題編號 | 通過／問題編號 | 待修／待複核／通過 |

使用者可以回覆「騎兵 135° 槍桿穿手」，我們能直接重現，不必重新描述整段動畫。

**D．V1.4 基礎上需要完成的大項**

**D1．大廳重整：先選玩法，再看條件，再擺陣｜必做**

承接 V1.4 裁決 B23、B25：

- 頂部只顯示模式、雙方、規則摘要與續局狀態。
- 左側顯示本戰條件，中央棋盤，底部兵種卡，右側選取兵種說明。
- `Beats／Fears` 改成完整本地化的克制／被克制區，不擠在擺陣頂欄。
- 進階七類規則收進抽屜式編輯器，主畫面只顯示與標準不同之處。
- 契約、貼紙、巨獸、宿敵的效果先摘要；選取可展開詳細條件。
- 非法陣型直接標出哪隻兵、哪個條件，提供定位。
- 開戰是唯一主要動作；清空、載入、匯入降低視覺權重。
- 設定頁開關與規則編輯器使用同一套控件行為。

**D2．結果頁重整：讓玩家知道下一步與發生原因｜必做**

承接 V1.4 裁決 B25：

- 第一層：勝負、耗時、剩餘戰力、關卡／契約達成狀態。
- 主要按鈕依模式變成下一站、下一局或再試一次。
- 第二層：重播、時光機、統計。
- 分享卡、GIF、出題、接力收到「分享與工坊」。
- 損失原因使用可查證事件，例如「第 24 秒右路失守」，點擊跳到重播。
- 不把相關性寫成因果；無法證明時顯示事件描述。
- 競猜明示原先選擇、實際勝負、差距與得分公式。
- 車輪戰明示留下哪些殘兵；雙封蠟顯示三封總結果。

**D3．大量混戰：整理地面、棋子、飛行物與事件層級｜必做**

- 地面先畫範圍與機關；角色依腳點排序；空中飛行物按高度及必要遮擋處理。
- 機關預警、時停、衝鋒／破陣等關鍵訊息高於普攻裝飾。
- 飄字在短時間窗合併，治療與傷害分流，重要狀態不合併掉。
- 同類爆炸保留各自實際位置，減少的是煙塵與殘片。
- 選取單位顯示目標、狀態及受遮擋輪廓。
- 事件列可篩選隊伍與事件類型，點擊定位／跳重播。
- 簡化模式保留敵我、傷害來源與危險區域。

這符合 Riot 對特效層級、輪廓與減少雜訊的設計原則；此處是對本作的具體套用。[Riot 原文](https://www.leagueoflegends.com/en-us/news/dev/clarity-in-league/)

**D4．新玩法平衡與流程補完｜該做**

不再只看隨機陣型總勝率。

- 巨獸：近戰斷臂路線、純遠程、混編、廉價大量兵分開驗證。
- 車輪戰：殘兵累積是否滾雪球、支援兵是否過強、最低預算補正是否可利用。
- 輪抽：先後手、卡池組合、AI 選卡與實際可部署性。
- 雙封蠟：先封／後封、平手、交接資訊是否洩漏。
- 遠征：契約永久加成、貼紙、事件獎勵的疊加上限與強勢組合。
- 每週棋盒：題目種子、卡池、對手與規則摘要固定保存。
- 幽靈軍團：保留既有 ID；修改內容另開版本，不能讓已通關 ID 指向另一陣型。
- 測試使用鏡像換邊、固定代表陣、隨機陣與刻意尋找漏洞的陣型。
- 先建立基準，再決定調數值；任何改戰鬥的調整都走版本與規則碼。

**D5．資料、代碼與重播生命週期｜必做**

- 匯入先預覽類型、版本、模式、規則差異與合法性。
- 對損毀、過長、未知欄位、不合法兵種、越界位置提供明確錯誤。
- 舊重播支援時使用對應規則；不支援時明示，不能用新版偷偷重算。
- 分享檔標示遊戲版本、規則版本、數值摘要。
- 設定、規則、進度各自遷移與備份。
- 匯出中切頁、退出、磁碟滿與失敗都能恢復，不留下無限等待。
- 模式切換繼續驗證每日、每週、車輪戰、封蠟與遠征狀態互不污染。
- 舊金標準與對戰指紋列為回歸門檻。

**D6．四語與大字級收尾｜該做**

- 簡中、日文優先校對玩法、勝敗、資料刪除、契約與規則用語。
- 統一兵種名、數量詞、時間單位與技能名。
- 所有新設定說明、動作名稱、規則差異都進翻譯流程。
- 驗證文字換行、焦點捲動、長名稱與數值變動。
- 未校對語言繼續明示狀態；程式版面檢查不能取代語意校對。

**D7．Steam 與 Deck 前置｜該做；外部實測獨立列管**

- Steam 排行榜後台建置、測試資料隔離、上傳／下載與離線補送實測。
- 成績攜帶題目版本、規則摘要與必要驗證資料。
- Cloud 做兩裝置衝突、舊檔、新檔與中斷復原測試。
- 手把全流程、重綁、熱插拔、文字輸入與按鍵圖示。
- Deck 驗證字級、效能、功耗、休眠喚醒、觸控與匯入輸入法。
- Steam 缺席時核心玩法正常運作；排行榜入口顯示實際狀態。
- 不把「程式已接」寫成「後台／實機已驗證」。

Steam 相容性判定依平台審查與實際裝置結果，提案中的測試不能自行視為認證。[Steamworks 文件](https://partner.steamgames.com/doc/steamdeck/compat)

**D8．可新增玩法：戰術試驗桌｜可做**

優先於再增加一個獨立大型模式：

- 任選雙方兵種、數量、位置與既有規則。
- 一鍵鏡像、重置、連跑固定種子組。
- 指定觀察兵種、顯示狀態、慢速與逐格。
- 保存試驗碼，從圖鑑直接進入。
- 使用同一模擬器，不做另一套假戰鬥。
- 自訂試驗與正式紀錄、成就、排行榜分開標示。

用途同時涵蓋玩家學習、角色檢查、平衡重現與問題回報。
