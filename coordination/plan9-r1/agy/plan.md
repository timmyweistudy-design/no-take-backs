## 2. V1.0 的定義
- 第九輪開工先打 tag `v1.0-base`，版本號統一：App 版本單一來源，規則版本獨立。
- **出貨門檻**：所有自動驗收綠；角色走路腳不滑（有量測）；每個畫面通過「一眼看懂」清單；真人試玩至少 5 場（使用者執行）；Steam 480 實測（使用者執行）。
- 不做：原生線上對戰（維持 v1.1）、新增第 21 種以上的兵、付費內容。

## 3. 角色與動畫（需求 1）
### 3.1 步態系統（最優先）
- **相位由實際位移算**：畫面層每隻累積位移，`phase += 位移 / 步長 × TAU`。減速圈、碎石、被推、變速重播都自動對。
- 這是純畫面，不進模擬，不影響指紋。
- 每種兵一筆步態資料：類型、步長、起伏、手擺幅度。

| 步態 | 兵種 | 要點 |
|---|---|---|
| 雙足 | 劍士、盾兵、弓箭手、刺客、長槍兵、投彈兵、醫者、鼓手、狂戰士、骷髏法師、骷髏、吸塵貓、巫毒娃娃 | 接觸→下沉→通過→抬升四姿；腳貼地時往後移；手與武器反向擺 |
| 四足 | 騎兵的馬、爆爆羊 | 對角步、羊衝刺改跳奔 |
| 彈跳 | 史萊姆、小史萊姆、寶箱怪 | 位移集中在跳躍段，落地壓扁；空中不算滑 |
| 飄浮 | 幽靈、沙漏精靈 | 沒有腳，正弦上下＋裙擺／翅膀延遲 |
| 重踏 | 小石魔 | 長步長、低節奏、落地揚塵與微震 |
| 定點 | 孢子菇 | 不走，呼吸與噴孢子 |

- 走路格 6→8。畫不下就放棄逐格手繪，改成身體／腿分層貼圖（〔X〕評估）。
- **起伏只動上半身**，腳不離地（跳奔、彈跳例外）。

### 3.2 其他動作
- 被推小碎步；被擊退：後仰＋腳拖地揚塵；被吸：往前趴拖行；暈：頭上星星、身體搖；時停：整隻定格加冷色。
- 轉身 2 格壓扁翻面；起步與停步各 1 格前傾／後仰。
- 待機：重心換腳、偶爾小動作（看武器、打哈欠、史萊姆抖動）。
- 攻擊：現有三段式保留；箭、火罐、骷髏法師法術的出手點要對準武器尖端（列表驗）。
- 死亡：每種一個專屬倒法（史萊姆化開、幽靈消散、石魔碎裂、羊炸飛）。
- 表情：受擊、開戰、勝利、敗北（敗方垂頭）。
- 20 種兵每種一列「招牌動作」驗收表（走、攻、技能、死、勝）。

### 3.3 品質工具
- `tools/anim_lint`：部件連通、腳滑比（腳的地面速度／身體速度）、超框、跨格跳動；進 check。
- 開發用「動作檢視器」畫面：選兵種、選動作、慢放。
- 接觸表自動產出，給 Antigravity 看。

## 4. 地圖（需求 3）
### 4.1 原則
- 所有地圖**左右鏡像**（模擬鏡像測試要繼續成立）。
- 一格地形只有一條規則，看顏色就懂；不做視線遮蔽。
- 平原＋標準大小走舊路徑，位元組不變，舊代碼不受影響。其他地圖走新分支。
- 地圖只用於自由排兵；殘局、教學維持平原。

### 4.2 大小
| 大小 | 格數 | 建議金／人數 | 建議秒數 |
|---|---|---|---|
| 小 | 12×7 | 60／16 | 60 |
| 中（標準） | 16×9 | 100／24 | 90 |
| 大 | 20×11 | 140／32 | 120 |

鏡頭等比縮放，大地圖角色變小要驗讀得清楚。部署縱深依比例。

### 4.3 地形
| 地形 | 規則 | 例外 |
|---|---|---|
| 阻擋（岩、牆、樹、河） | 地面單位不能通過 | 幽靈可穿；箭和火罐飛過去 |
| 泥／雪（慢） | 移速 ×70% | 幽靈、沙漏精靈不受影響 |
| 道路／冰（快） | 移速 ×120%；冰上騎兵不減衝鋒 | |
| 高地 | 遠程射程 +0.5 格 | |
| 草叢 | 裡面的單位 2 格外不能被遠程選為目標 | |
| 岩漿噴口 | 每 8 秒預警 1 秒後噴發，範圍傷害，不分敵我 | |

### 4.4 五張新地圖（加原本平原共 6 張）
1. **雙橋河谷**：中央河流，2 座橋；中、大。遠程與幽靈強，逼人想走哪座橋。
2. **低語森林**：草叢帶＋樹；寶箱怪、刺客、孢子菇舞台。
3. **冰湖雪原**：中間冰面快、兩側雪地慢；騎兵與羊。
4. **熔岩裂谷**：噴口節奏＋岩塊；要避開時機，翻盤多。
5. **遺跡祭壇**：柱列分割＋中央高地；小型戰鬥與搶高地。

### 4.5 模擬實作
- `W`/`H` 從常數改成場次欄位；地形是整數矩形／圓清單，含在模擬雜湊與規則代碼（NTBR4）。
- **尋路**：載入時建 0.5 格導航格（最多 40×22），對少量路標預算全對最短路下一跳；單位直線可達就直走，否則朝路標走；每 8 tick 才重算一次，只用整數。
- 擋牆不能讓單位卡死：卡住偵測＋時間到照原判定。
- 工具：地圖 JSON、驗證（鏡像、可達、部署面積、噴口週期）、golden_map。
- AI：`formations.to_free` 要避開阻擋；模板依地圖加權；困難 AI 本來就用模擬挑陣，改動小；反制庫只用標準。
- 平衡：每圖每大小跑 army／cheese／repl；只有平原中型有「平衡認證」，其他是「娛樂」徽章，通過驗收才改。

### 4.6 美術與音效
- 每圖一張背景，載入時烘成貼圖；前景物件和角色依 y 排序，能遮擋。
- 素材：現有 Cainos 只有草地。其他地貌程式繪製優先，缺口用 CC0（Kenney）；要記到授權檔。
- 每圖一段環境音＋配色；黃昏／夜晚當外觀選項（不影響規則）。

## 7. 全畫面精緻化（需求 5）
### 7.1 目前看到的問題
- 大廳與設定大片留白，框裡字小；戰場鮮豔，選單是灰藍平板，兩邊像不同遊戲。
- 很多區塊只有文字沒有圖示；標題選單字小。
- 主要動作不夠突出；頁籤太多同層。

### 7.2 設計系統
- 色彩、圓角、間距（8 的倍數）、層次全部變成常數；木牌＋羊皮紙主題呼應 Q 版戰場。
- 自繪圖示 40 個（金幣、人數、時間、地圖、劍、盾…），圖示＋文字成對。
- 元件庫：按鈕（一般、懸停、按下、停用、焦點）、頁籤、卡片、滑桿、切換、提示框、徽章。
- 每個畫面一個主要動作；過場 0.25 秒；標題是真戰鬥背景。

### 7.3 畫面清單
標題、大廳、地圖選擇（新）、部署、戰鬥 HUD、暫停、結果、詳細數據、重播、覆盤、殘局列表、戰役地圖（新）、遠征、圖鑑、設定、按鍵、個人頁（新）、代碼輸入、確認框、製作名單。每一個要有：版面圖、主要動作、空狀態、手把焦點、音效。

### 7.4 音效與音樂
- 介面：懸停、確認、返回、切換頁籤、滑桿、錯誤、彈窗、解鎖。
- 戰鬥：每兵種腳步（小音量、數量上限）、技能音分層、擊中依武器材質、地形腳步。
- 音樂：標題、部署、戰鬥（已有分層）、結果 stinger、每地圖環境音；介面音與音樂匯流排分開、技能時壓低音樂。
- 現在全是合成音；評估 Kenney／Freesound CC0 混用，只用 CC0 並記授權。

### 7.5 看懂度驗收
- 版面檢查新增：左緣對齊、留白比例、對比度、圖示與文字配對、主要按鈕唯一。
- 每個畫面給 Antigravity 看一次，問「3 秒內看得懂要做什麼嗎」。

## 8. 程式與資料夾（需求 6）
- `game_screens.gd` 拆成 `ui/screens/*.gd`；`battle_view.gd` 拆 HUD、特效、單位繪製；`art.gd` 拆 `ui/units/*.gd`（每種兵一檔）。
- `tools/` 分 `check/`、`balance/`、`gen/`、`dev/`。
- `coordination/` 61 個資料夾打包到 `coordination/archive/`，只留最新；`.log` 不進 git。
- `docs/`：現行放根目錄，舊方案、舊截圖進 archive；`docs/shots-v7` 移除。
- 專案外 `projects/ntb-*` 確認內容後移到 `build/old-shots/`（不進 git）或刪除。
- 專案用的暫存一律放 `build/tmp/`，`tools/clean.sh` 一鍵清。
- `play.bat` 不寫死使用者路徑。

## 9. 省 token、skills、效能、驗收加速（需求 7）
### 9.1 驗收加速
- **分片平行**：測試、金標準、相容、鏡像都支援 `--shard`，同時跑 8～12 個行程；目標統一檢查從 45 分降到 8 分內。
- **依變更挑檢查**：`tools/check.py` 用檔案雜湊判斷，只改 UI 就不跑金標準；結果快取到 `build/check-cache`。
- **每項測試計時**，慢的前 20 名優先改。
- 版面檢查分級：快速（1 語言、1 字級、只拍受影響畫面）／完整（里程碑）。
- 所有工具輸出單行結論，細節進檔；逾時用 PID 檔收 Windows 程序。

### 9.2 省 token
- 專案加 `CLAUDE.md`（60 行內）：入口、指令、鐵則、不要重讀的檔。
- 專案 skills（`.claude/skills/`）：`ntb-check`、`ntb-review`（三方固定流程與字數上限）、`ntb-balance`、`ntb-shots`、`ntb-unit`。長流程只在需要時才載入。
- 使用者層 MEMORY.md 瘦身：每個專案只留 1 行。
- 看圖一律先拼接觸表；審查提示模板化，回覆字數上限。
- 背景跑、只回結論；不把長日誌讀進對話。

### 9.3 遊戲效能
- 效能門檻用「同次對照基準」的比值（機器會差 3 倍）。
- 圖集格數增加要算記憶體；步態資料用分層貼圖可能比加格省。
- 目標：48 隻 60fps（中階）、30fps（最低規格）；啟動到標題 3 秒內。
